# AgentMail

Desktop-агент на Compose Multiplatform и JetBrains Koog. Он проверяет корпоративный IMAP-ящик,
локально находит точный тег пользователя (например, `@dmitry.bykov`), кратко пересказывает найденное
письмо через локальную Ollama или корпоративный OpenAI-compatible endpoint и отправляет уведомление в Telegram.

## Требования

- JDK 17+
- IMAP-доступ к корпоративной почте (пароль или app password)
- Telegram bot token и chat ID
- Для автоматизации GitLab: корневой HTTPS URL инсталляции и access token с правом изменять issues
- [Ollama](https://ollama.com/) с установленной chat-моделью либо корпоративный Base URL, model ID и API key

Для локальной обработки запустите Ollama и установите модель, например:

```bash
ollama pull qwen3:8b
ollama serve
```

AgentMail подключается только к `http://localhost:11434`, получает список локальных моделей через
Ollama API и не требует API key. Cloud-модели и embedding-модели в список выбора не включаются.

## Запуск

```bash
./gradlew run
```

Собрать нативный дистрибутив для текущей ОС:

```bash
./gradlew packageDistributionForCurrentOS
```

## Безопасность и поведение

- Пароль почты, корпоративный LLM API key, Telegram token и GitLab access token сохраняются в системном keyring, а не в Preferences.
- IMAP открывается в `READ_ONLY`; флаг `SEEN` не меняется.
- При первом запуске агент начинает с конца ящика и не пересылает историю.
- До модели доходит только письмо с точным совпадением тега; вложения не читаются.
- При ошибке модели Telegram получает локальный фрагмент письма.
- История Telegram хранится локально в SQLite; повторно найденное письмо автоматически не отправляется.
- Если задан GitLab Base URL, агент распознаёт письма `Merge request !... was merged`, проверяет MR через API и для ветки вида `feature/issue-233-2` обновляет issue `233`: добавляет `Reviewed` и удаляет `Merge Request`.
- Строка merge должна быть точной темой или первой непустой строкой тела; поздние и процитированные вхождения игнорируются. Issue определяется по `source_branch` из GitLab API, а не по тексту `Branches` в письме.
- GitLab-ссылка принимается только с настроенного trusted Base URL; редиректы отключены, access token передаётся только этому серверу и хранится в системном keyring.
- Успешное GitLab-действие отдельно фиксируется в SQLite и повторно не выполняется. Временный сбой допускает безопасный повтор идемпотентного обновления labels.
- Неопределённый результат доставки блокирует автоповтор, чтобы не создавать дубли.
- Закрытие окна скрывает AgentMail в системный трей, не останавливая мониторинг. Если системный трей недоступен, окно сворачивается в панель задач.
- Окно можно вернуть через значок в трее; пункт «Выйти» полностью завершает приложение. Без системного трея команда «Выйти» доступна в меню окна AgentMail.
- На macOS при доступном системном трее команда Quit из Dock или `Cmd+Q` также скрывает окно; для полного завершения используйте пункт «Выйти» в трее.
- Мониторинг работает, пока приложение не завершено и компьютер не находится в режиме сна.
- В режиме Ollama письмо не отправляется внешнему LLM, но уведомление всё равно передаётся в Telegram.
- Перед использованием корпоративной модели и Telegram согласуйте передачу данных с политиками компании.
- Пустой GitLab Base URL полностью отключает GitLab-автоматизацию и не требует access token.
- Письма, уже находящиеся за сохранённым IMAP-курсором, автоматически не переигрываются; для проверки исправления нужно новое merge-уведомление.

Ollama и корпоративная модель используют `OpenAILLMClient` Koog. Для Ollama заданы локальный Base URL
и стандартный `v1/chat/completions`; корпоративный режим сохраняет настраиваемые HTTPS Base URL,
chat completions path и model ID.

Для Google Workspace используйте пресет в интерфейсе: `imap.gmail.com`, порт `993`, IMAPS и `INBOX`.
Обычно логином является полный корпоративный email. При включённой двухфакторной аутентификации нужен
app password; если администратор Workspace запретил парольную IMAP-аутентификацию, потребуется OAuth2.
